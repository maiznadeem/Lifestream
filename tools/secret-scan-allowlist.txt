# Reviewed allow-list for tools/scan-artifacts.ps1 when it scans the SOURCE tree (secret-scan.yml, "repository" job).
# One entry per line:  path|rule|sha256
#   path    ONLY a test project's throw-away secrets file, tests/<Project>/TestSecrets.cs (anything else makes the scanner exit 2)
#   rule    the rule the scanner reports (PasswordValue, UserIdValue, ...)
#   sha256  hex SHA-256 of the matched LINE's bytes with the trailing CR/LF removed. Editing the line changes the hash, so the
#           entry stops matching and the line is flagged again. Get it with a LOCAL run:
#             pwsh tools/scan-artifacts.ps1 -Path tests -GitTracked -ShowMatchHashes   (refused in CI: no hash reaches a CI log)
# Test passwords are not allow-listed one by one: every test project keeps them in its TestSecrets.cs, and
# tests/infra/TestSecrets.Tests.ps1 fails on a password-shaped literal in any other test file. The constants there are named so the
# scanner has nothing to flag; an entry is only needed if a TestSecrets.cs line itself is flagged.
# Never add a real credential here; remove the credential instead.
